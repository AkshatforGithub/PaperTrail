# PaperTrail

Citation-verified question answering over arXiv computer-science papers. PaperTrail retrieves passages with hybrid search (dense vectors + Postgres full-text, fused with reciprocal rank fusion), reranks them with a cross-encoder, and generates answers that must cite their sources or abstain. The retrieval pipeline is measured on a frozen, hand-reviewed 70-question evaluation set.

## Headline result

Top-5 chunk recall rose from **68.6% to 87.1%** (MRR@10 from 0.535 to 0.812) on a 70-question hand-verified eval set, using hybrid vector + full-text search with reciprocal rank fusion and cross-encoder reranking. On the 50 held-out test questions, recall@5 rose from 68% to 84%.

## Architecture



- **Corpus:** 100 cs.CL arXiv papers, frozen in `evaluation/corpus.txt`; 6,084 chunks. Chunks never cross section boundaries, references are cut, and the abstract is stored as chunk 0.
- **Embeddings:** `BAAI/bge-small-en-v1.5` (384-dim, normalized, with the query prefix on questions).
- **Reranker:** `cross-encoder/ms-marco-MiniLM-L-6-v2`.
- **Generation:** Groq OpenAI-compatible API. The prompt numbers the top-5 chunks as [1] to [5] and requires a `[n]` citation after each sentence, or the exact abstention sentence "I can't find this in the indexed papers."
- **API:** FastAPI with `/health` and `/ask`.

## Evaluation method

- **70 questions over 52 papers**, drafted by an LLM from sampled chunks and then hand-reviewed. Question types: numeric, finding, method, definition, comparison.
- **Frozen:** `questions.jsonl` and `corpus.txt` are never edited after freezing.
- **Fixed split:** 20 dev / 50 test questions (seed 13). The dev set is too small to tune on, so conclusions are reported on all 70 and on the 50 test questions.
- **Gold labels are (arXiv ID, verbatim evidence phrase), not chunk IDs**, so chunking experiments reuse the same questions. A *chunk hit* means the right paper and the evidence phrase inside the chunk (case, whitespace and quote folded). A *paper hit* means any chunk from the right paper.
- **Metrics:** recall@k and MRR@10, chunk-level and paper-level.

## Retrieval results

Chunk-level, chunk size 800 / overlap 100:

| Retriever | Recall@5 (all 70) | MRR@10 (all 70) | Recall@5 (test 50) | MRR@10 (test 50) |
|---|---|---|---|---|
| Vector (baseline) | 68.6% | 0.535 | 68% | 0.501 |
| Keyword (Postgres FTS) | 68.6% | 0.438 | 64% | 0.416 |
| Hybrid (RRF) | 78.6% | 0.619 | 76% | 0.589 |
| Hybrid + cross-encoder rerank | 87.1% | 0.812 | 84% | 0.804 |

- Paper-level recall@5 on all 70 questions: 88.6% for vector, 95.7% for hybrid + rerank.
- Reranking fixed 13 questions that the baseline missed and broke none.
- Latency per query: about 11 ms for vector, about 172 ms for hybrid + rerank.
- Keyword search alone is no better than vector search, but it answers different questions correctly, which is why fusing the two helps.

### Chunk-size experiment (plain hybrid, no reranker)

| Chunk size | Recall@5 (all 70) | Recall@5 (test 50) |
|---|---|---|
| 400 | 80.0% | 80% |
| 800 | 78.6% | 76% |
| 1200 | 72.9% | 66% |

400 vs 800 is a tie within noise (one question is 1.4 points), so 800 stays as the default. 1200 is clearly worse. 1200 looked best on the 20 dev questions and was worst on test, which is why the dev set is not used for tuning. Chunk sizes were not tested together with the reranker.

## Generation quality

Measured on 30 test questions. Answers were generated by **gpt-oss-20b** and judged by a different model family, **qwen3.8-27b**, one judgment per cited sentence.

| Metric | Value |
|---|---|
| Abstained | 6.7% (2 of 30) |
| Faithfulness (cited sentences judged supported) | 96.6% (28 of 29) |
| Uncited sentences | 0.0% |
| Answers passing the structural citation check | 96.4% (27 of 28 non-abstained) |

How far to trust the judge:

- **Judge sanity check:** the judge accepted 15 of 15 real numeric claims and 0 of 15 copies with every number tripled.
- **Hand-check:** the one flagged sentence was a genuine error. The model presented the three components of one method (SliderQuant) as general accuracy-recovery techniques. All 10 randomly sampled passed answers were correct against their cited sources. An earlier gpt-oss-120b judge had flagged a correct sentence on a smoke run, so judge choice matters.
- **Small sample:** 29 sentences means one sentence moves the figure by about 3 points. Treat it as a sanity check rather than a benchmark. The 10 sampled passed answers were mostly single-fact lookups.

`Answer.verified` in the API is a structural check only (valid citations, none missing). It does not confirm that a claim is true.

## Run it

```bash
docker compose up -d                       # Postgres + pgvector
python -m venv .venv && source .venv/bin/activate
pip install -e .
cp .env.example .env                       # then add your GROQ_API_KEY

make ingest ARGS="--ids-file evaluation/corpus.txt --reingest"

python scripts/search.py "your question"   # retrieval only

uvicorn papertrail.api.main:app --reload
curl localhost:8000/health
curl -s -X POST localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"question": "your question", "verify": false}'
```

Interactive API docs are at `http://localhost:8000/docs` while the server runs.

```bash
python evaluation/run_eval.py --name my_run            # new name each time
python evaluation/compare_runs.py --md                 # results table
python evaluation/run_faithfulness.py --name my_faith --n 30 --judge-model MODEL
python evaluation/judge_sanity.py --name my_faith --judge-model MODEL --max 15
python evaluation/hand_check.py --name my_faith        # flagged + sampled answers with sources
pytest                                                 # DB tests need Docker up
```

## Limitations

- **Small eval set:** 70 questions, so one question is 1.4 points. Differences are judged by questions fixed vs broken, not by headline percentages alone.
- **Unreachable questions:** a few questions (q014, q029, q032) do not name their paper, so recall is capped near 90%.
- **No acronym slice:** acronym-style questions were deliberately left out as too costly to write by hand.
- **Chunk-level metric:** it slightly penalizes small chunks.
- **LLM-judged faithfulness:** the judge is a model, only spot-checked by hand, on a small sample.
- **Corpus quality:** one paper (2610.01378) parses poorly and yields only 4 chunks. It is excluded from question drafting.
- **Scope:** 100 cs.CL papers only. Results may not carry over to other fields or larger corpora.
- **Reranker:** a general-purpose MS MARCO model, not trained on scientific text.
